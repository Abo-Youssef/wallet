# my Wallet — نظام متابعة وإدارة الممتلكات

نظام عربي مشترك بين مدير ومساعد لمتابعة العقارات والوحدات والسيارات والعاملين والعقود والمستحقات والفواتير والمهام. الواجهة متجاوبة للهاتف والتابلت والكمبيوتر، بخط عربي محلي وأرقام إنجليزية مع قبول الأرقام العربية والفارسية عند الإدخال.

**الحالة في 18 أكتوبر 2026:** النسخة الحالية منشورة على [my Wallet](https://wallet.soudy26.workers.dev/) وتستخدم Neon PostgreSQL عبر Cloudflare Hyperdrive، ويحمي Cloudflare Access الواجهة والـAPI. جداول النظام ودور التشغيل المحدود موجودان في فرعي development وproduction. التحقق المنجز وحدوده والخطوة التالية في [HANDOFF.md](HANDOFF.md).

البنية: **React + Vite ← Cloudflare Workers API ← Hyperdrive ← Neon PostgreSQL**. معرفا حساب Cloudflare وHyperdrive في `wrangler.toml` حقيقيان؛ لا تستبدلهما بأمثلة الدليل عند متابعة هذا المشروع. روابط الاتصال وكلمات المرور خارج المستودع.

- [SETUP.md](SETUP.md): التشغيل المحلي والصيانة والنشر واستعادة قاعدة منفصلة.
- [HANDOFF.md](HANDOFF.md): الحالة الحالية والقرارات والاختبارات والمتبقي؛ لا يعيد خطوات تجهيز الموارد القائمة.
- هذا الملف: خريطة المصدر وقواعد العمل وأوامر الاستخدام وحدود النظام.

## خريطة المشروع

```text
src/
  client/                واجهة React والصفحات والنماذج والحالة والأنماط
    main.jsx             نقطة دخول الواجهة
    demo.mjs             بيانات المعاينة المستقلة
  server/                API والمصادقة واتصال PostgreSQL والنسخ والاستعادة
    worker.mjs           نقطة دخول Cloudflare Worker
    postgres.mjs         اتصال قاعدة البيانات والمعاملات
  shared/                الحسابات وقواعد العمل المشتركة
    finance.mjs          محرك الحساب بالهللة
database/
  postgres/              ترحيلات PostgreSQL الحالية
  permissions.sql        صلاحيات حساب التشغيل wallet_app
  migrations/            ترحيلات SQLite القديمة للتحقق من التوافق
scripts/                 التشغيل والبناء والترحيل والنسخ والاستعادة
tests/                   اختبارات الخادم والواجهة والبناء والبيانات
HANDOFF.md               حالة النظام والقرارات والتحقق والمتبقي
wrangler.toml            إعداد Cloudflare والأصول وربط HYPERDRIVE
.env.example             نموذج إعداد محلي دون أسرار فعلية
package.json             الاعتماديات والأوامر
package-lock.json        إصدارات الاعتماديات الثابتة
```

تُولّد `dist/` و`preview-dist/` و`معاينة_تفاعلية.html` عند البناء ولا يلزم حفظها في Git. الاختبارات والترحيلات وملف القفل والوحدات المشتركة مستخدمة؛ حذفها لا يبسط تشغيل التطبيق.

مسار الحفظ: **نموذج الواجهة ← API ← التحقق من الهوية والصلاحية والمدخلات ← PostgreSQL وسجل التدقيق ← تحديث الملخص والشاشة**. GitHub يحفظ الكود، والمتصفح يعرض البيانات؛ لا يمثل أي منهما قاعدة المحفظة.

## اختيار طريقة التشغيل

| الطريقة | البيانات والحفظ | الاستخدام |
| --- | --- | --- |
| `npm run dev:local` أو `npm run dev` | PostgreSQL المحدد في `.env`؛ البيانات تبقى بعد الإغلاق | تجربة الحفظ والصلاحيات محليًا |
| `npm run dev:demo` | يضيف بيانات توضيحية إلى قاعدة تطوير فارغة فقط | تجربة نموذج محفظة جاهز |
| `npm run preview:build` | ملف HTML مستقل ببيانات اصطناعية دون حفظ | مشاهدة الواجهة دون خادم أو قاعدة |
| `npm run deploy` بعد الإعداد | Workers وHyperdrive والقاعدة المستضافة | نشر التطبيق الفعلي |

**التشغيل المحلي أصبح دائم الحفظ في PostgreSQL.** لا يمسح البيانات عند البدء أو الإيقاف، ولا يضيف بيانات تجريبية إلا بأمر `dev:demo`. يرفض أمر البيانات التجريبية القاعدة التي تحتوي سجلات. احتفظ بقاعدة تطوير منفصلة عن الإنتاج.

## التشغيل المحلي للمرة الأولى

المتطلبات: **Node.js 24 أو أحدث** وPostgreSQL يعمل على جهازك أو على قاعدة تطوير مستضافة. الإصدار المحدد لـNode في `.node-version` هو `24.14.1`.

1. عند متابعة هذا المشروع، استخدم فرع Neon `development` القائم. أنشئ قاعدة تطوير مستقلة فقط عند إعداد بيئة جديدة؛ لا تستخدم production للتجربة.
2. ثبّت الاعتماديات بـ`npm ci`. إن لم يوجد `.env`، انسخ القالب دون الكتابة فوق ملف موجود:

```powershell
npm ci
if (-not (Test-Path -LiteralPath .env)) { Copy-Item -LiteralPath .env.example -Destination .env }
```

3. ضع في `.env` اتصال development بدور التشغيل **wallet_app**. ملف `.env.admin` منفصل لاتصال مالك development ويُستخدم صراحةً لأعمال الصيانة؛ لا تضع المالك في ملف تشغيل النظام.
4. الجداول والصلاحيات في Neon الحالي مجهزة بالفعل. لقاعدة جديدة فقط، طبّق الترحيلات بدور المالك ثم أنشئ `wallet_app` وطبّق `database/permissions.sql` وفق [SETUP.md](SETUP.md):

```powershell
node --env-file=.env.admin scripts/migrate-postgres.mjs
```

5. شغّل النظام:

```powershell
npm run dev:local
```

افتح <http://127.0.0.1:43128>. يتيح شريط التطوير تبديل المدير والمساعد بهويات اختبار محلية؛ بيانات الحفظ الفعلية تذهب إلى قاعدة التطوير. لا تحتاج Cloudflare Access للتجربة المحلية، لكنها لا تختبر تسجيل الدخول السحابي.

بعد تعديل المصدر، أوقف المشغّل بـ`Ctrl+C` وأعد تشغيله لتحديث البناء. لتغيير المنفذ عدّل `PORT` في `.env` أو استخدم `$env:PORT = '43130'` في PowerShell. العنوان المحلي لا يفتح من هاتف أو جهاز آخر. `--empty` القديم خيار توافق لا يمسح قاعدة البيانات.

## البناء والاختبارات

```powershell
npm run build
npm run preview:build
```

البناء الأول ينتج `dist/` دون نشر. الثاني يولّد `معاينة_تفاعلية.html`، ويمكن فتحه مباشرة؛ تُستبعد بياناته وأدوات تبديل الدور من بناء الإنتاج.

**اختبارات PostgreSQL تحتاج `TEST_DATABASE_URL` لخادم اختبار منفصل** وحساب يملك صلاحية `CREATE DATABASE`. ضعه في `.env` أو بيئة الطرفية؛ لا توجّهه إلى خادم البيانات الفعلية. تنشئ أدوات الاختبار قواعد بأسماء `wallet_test_...` ثم تحذف القواعد التي أنشأتها فقط، ولا تعيد تهيئة القاعدة المذكورة في رابط الاختبار.

```powershell
npm test
```

يشغّل الأمر اختبارات Node ثم React. لتشغيلهما منفصلين:

```powershell
npm run test:core
npm run test:react -- --maxWorkers=2
```

تشمل التغطية الحساب بالهللة والتواريخ والترحيلات والصلاحيات وتكرار الطلبات وتزامن الحفظ والإخلاء والحجز والاستعادة والجلسات والنماذج. اختبارات الواجهة تعمل في DOM محاكى. نجاح الاختبارات المحلية لا يثبت تكامل Neon وHyperdrive وCloudflare Access على النطاق الحقيقي؛ يلزم اختبار سحابي من البداية إلى النهاية قبل الاعتماد.

## الحسابات وقواعد العمل

| العملية | المساعد | المدير |
| --- | --- | --- |
| قراءة المحفظة والتقارير والتصدير الشهري | متاح | متاح |
| إضافة وتعديل الأصول والعقود والدفعات والمصروفات والمهام | متاح | بعد تفعيل وضع المساعد من «المزيد» |
| الإغلاق والأرشفة والتصحيح | متاح وفق شروط الاتساق | وفق الشروط نفسها وفي وضع المساعد |
| سجل العمليات وإخفاء بند من عرضه | غير متاح | متاح؛ التدقيق الأصلي يبقى محفوظًا |
| تنزيل النسخة الاحتياطية وفحصها | غير متاح | متاح |
| استبدال البيانات بنسخة احتياطية | غير متاح | يتطلب وضع المساعد والتأكيد |

المحفظة مشتركة. يبدأ المدير بوضع الاطلاع؛ تفعيل وضع المساعد لا يغيّر هويته، وتُسجل العمليات باسمه الحقيقي. تعود الصفحة المحملة من جديد إلى وضع الاطلاع. يفرض الخادم الصلاحيات، إضافة إلى الواجهة. حساب PostgreSQL `wallet_app` حساب تقني للخادم؛ ليس مستخدمًا يتلقى مدير المحفظة أو مساعده كلمة مروره.

- يُسجّل العقار مرة واحدة ثم تُضاف وحداته وعقودها. حفظ الوحدة ثم إلغاء نموذج العقد يترك الوحدة محفوظة.
- انتهاء مدة الإيجار أو سداد قيمته لا يجعل الوحدة متاحة؛ يلزم حفظ تأكيد الإخلاء. الإنهاء المبكر يحفظ المديونية ولا يمنح خصمًا تلقائيًا.
- يمكن تأجير الوحدة بعد الإخلاء مع متابعة دين المستأجر السابق. الإغلاق المالي منفصل عن الإخلاء ويتطلب تصفية المتبقي.
- الحجز اليومي للاستراحة ليوم واحد بتوقيت الرياض؛ يمنع التداخل. إلغاؤه يحرر اليوم ويحفظ التحصيل والدين دون رد أو إسقاط تلقائي. تغيير اليوم أو القيمة يتطلب إلغاء القديم وإنشاء جديد.
- المبالغ محسوبة بالهللات الصحيحة. الاستحقاق يتبع جدول العقد؛ الداخل والخارج الفعليان يتبعان تاريخ تنفيذ الحركة. صافي التدفق ليس رصيدًا بنكيًا أو ربحًا محاسبيًا.
- يُراجع تغيير مبلغ التحصيل وأثره على نهاية جدول الدفعات قبل التأكيد. التحصيل الجزئي يترك المتبقي مستحقًا.
- عند غياب تأكيد الحفظ، أعد الطلب نفسه من النافذة نفسها. عند تبديل الجهاز أو إغلاق الجلسة راجع السجل قبل إعادة الإدخال.

## إعداد النشر والترحيلات

في الإنتاج يقرأ Worker اتصال `HYPERDRIVE` بدور `wallet_app`. معرف الربط الحقيقي محفوظ في `wrangler.toml`، وQuery caching معطل بالفعل حتى تعكس القراءة الحفظ الأخير. حافظ على `nodejs_compat` و`run_worker_first = true` و`preview_urls = false`.

الدخول عبر Cloudflare Access، مع سياسة تسمح لبريدَي الحسابين. يلزم ضبط `ACCESS_TEAM_DOMAIN` و`ACCESS_AUD` و`MANAGER_EMAIL` و`ASSISTANT_EMAIL` كأسرار تشغيل. راجع [دليل الإعداد](SETUP.md) للخطوات والأوامر؛ حفظ `.dev.vars` محليًا لا يضبط أسرار الإنتاج. معرّف حساب Cloudflare الحالي مثبت في `wrangler.toml`؛ تحقق من الحساب قبل أي نشر. سياسة Access المعتمدة تغطي All traffic.

الترحيل يستخدم `DATABASE_URL` وملفات `database/postgres/` ويحتاج حساب المالك. استخدم `node --env-file=.env.admin scripts/migrate-postgres.mjs` للتطوير، أو ملف إدارة الهدف المقصود صراحةً. اختصار `npm run migrate` يحمّل `.env` الخاص بالتشغيل؛ لا تستخدمه لتبديل صلاحيات التشغيل أو تتجاوز خطأ صلاحياته. لا تعدّل ترحيلًا مطبقًا؛ أضف ترحيلًا جديدًا بعده. قبل ترقية بيانات فعلية، خذ نسخة وجرّب على قاعدة منفصلة. نشر التطبيق لا ينقل البيانات أو يطبق الترحيلات تلقائيًا.

ملفات `database/migrations/` التسعة و`scripts/restore-backup.mjs` تخص **SQLite وD1 القديمين**. بقيت لفحص نسخ JSON القديمة واختبارات التوافق وتاريخ المخطط، وليست قاعدة الإنتاج أو مسار النشر الحالي. نسخة JSON ما زالت تحمل `format_version:2` و`schema_version:9` للتوافق؛ هذا مختلف عن سجل ترحيلات PostgreSQL.

## النسخ والاستعادة

من حساب المدير: «المزيد ← نسخة احتياطية» لتنزيل JSON. للاستعادة اختر الملف وافحص الملخص، ثم فعّل وضع المساعد للمدير واكتب «استعادة» وأكّد الاستبدال. الفحص وحده لا يكتب بيانات؛ التنفيذ يستبدل الجداول التسعة كاملة في معاملة واحدة ويحفظ نسخة رجوع. نزّل نسخة الرجوع خارجيًا؛ الموجودة داخل القاعدة تُستبدل في الاستعادة التالية.

إذا تغيّرت البيانات بعد الفحص أو مرّت 15 دقيقة يلزم الفحص مجددًا. تُرفض الكتابات القديمة بعد الاستعادة حتى تحديث البيانات. عند انقطاع الاتصال أعد المحاولة من نافذة الاستعادة نفسها.

**حد استعادة JSON داخل التطبيق 10 MB لكل من الملف والحالة الحالية. هذا حد لمسار الواجهة، لا لسعة PostgreSQL أو حجم صفحة الويب.** الاستعادة المالية الكبيرة قد تتجاوز حدود CPU السحابية قبل بلوغ هذا الحجم؛ استخدم الأدوات الإدارية أدناه مع الاختبار.

| الأمر | الغرض والهدف |
| --- | --- |
| `npm run backup:check -- "C:/safe/wallet.json"` | فحص JSON دون تعديل بيانات |
| `node --env-file=.env.restore.admin scripts/import-postgres-backup.mjs --input "C:/safe/wallet.json"` | استيراد JSON إلى هدف جديد فارغ بعد تطبيق ترحيلاته |
| `node --env-file=.env.production.admin scripts/postgres-backup.mjs backup --output "C:/safe/wallet.dump"` | نسخة PostgreSQL من production إلى ملف جديد |
| `node --env-file=.env.restore.admin scripts/postgres-backup.mjs restore --input "C:/safe/wallet.dump"` | استعادة إلى هدف جديد فارغ دون تطبيق المخطط مسبقًا |

أدوات `.dump` تستخدم `pg_dump` و`pg_restore` وتتدفق مباشرة إلى الملف دون تحميل النسخة كاملة في JavaScript، وهي المسار الأنسب للنسخ الكبيرة. تحتاج أدوات PostgreSQL واتصالًا إداريًا مباشرًا غير مجمّع. استيراد JSON لا يخضع لحد المتصفح لكنه يحتاج ذاكرة تكفي الملف والتحقق منه. تعليمات `PG_BIN` وإنشاء الهدف والتحويل والرجوع في [دليل الإعداد](SETUP.md).

لا توجّه استعادة الأدوات إلى القاعدة العاملة. قبل تحويل التطبيق إلى الهدف الجديد، أعد إعداد `wallet_app` وصلاحياته، وطابق الأعداد والأرصدة وحالات الوحدات، واختبر الدخول والصلاحيات. احتفظ بالمصدر وأوقف الإدخال أثناء التحويل حتى لا تتوزع الكتابات بين قاعدتين.

للفحص التاريخي فقط: `npm run backup:legacy:verify -- "C:/safe/wallet.json" --output "C:/safe/legacy-check"` ينتج SQLite وSQL وتقرير تحقق في مجلد جديد. لا يحدّث PostgreSQL أو التطبيق المنشور.

JSON وملفات `.dump` غير مشفرة لمجرد كونها نسخًا. بصمة الملف تكشف تغيّره ولا تثبت هوية مصدره. احتفظ بنسخ مؤرخة خارج المشروع، وجرب الاستعادة. **لا توجد مهمة نسخ خارجية مجدولة تلقائيًا في المشروع.** اقتراح تذكير المساعد بإنشاء نسخة وتنزيلها لم يُنفذ؛ تنزيل النسخ والاستعادة ما زالا للمدير وفق الصلاحيات الحالية.

## حدود النسخة والعناية بالمصدر

التنبيهات داخل التطبيق فقط. لا توجد إشعارات هاتف أو بريد مجدول، ولا رفع مرفقات عقود، ولا عمل دون اتصال أو تعدد محافظ. بيانات العاملين غير مرتبطة برواتب وسلف. التصدير الشهري يعكس البيانات المحملة، وليس لقطة تاريخية ثابتة قبل التصحيحات.

يحمّل بدء التطبيق مجموعة بيانات المحفظة كاملة باستثناء سجل العمليات. PostgreSQL لا يجعل الواجهة غير محدودة؛ مع النمو نقيس وقت التحميل وCPU وحجم النقل، ثم نضيف تقسيم النتائج والحسابات المناسبة عند الحاجة. حدود خطط Neon وWorkers وHyperdrive وآثار المجاني موثقة في [SETUP.md](SETUP.md).

لا ترفع ملفات `.env*` الفعلية أو `.dev.vars*` أو النسخ الاحتياطية أو `node_modules` أو `dist` أو `.wrangler` إلى المستودع. الاستثناء الوحيد للبيئة هو القالب الفارغ `.env.example`. أبقِ `package-lock.json` والاختبارات والترحيلات. قواعد `.gitignore` لا تطبق تلقائيًا عند رفع الملفات يدويًا من موقع GitHub.
