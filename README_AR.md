# محفظتي 2.0 — React · إيقاع واضح

تطبيق عربي لمحفظة واحدة مشتركة بين مدير ومساعد. الواجهة مبنية بـReact وVite، والخادم بـCloudflare Workers وD1. النسخة 2.0 تعتمد الاتجاه البصري **«إيقاع واضح»**: واجهة فاتحة، وشريط جانبي بلون برقوقي عميق على الكمبيوتر، وتجربة عربية من اليمين إلى اليسار مناسبة للجوال.

التسليم يحتوي **المصدر، ومعاينة مستقلة للقراءة فقط، ومشغّل اختبار محلي مؤقت**. لم يُنشر على حساب Cloudflare فعلي، ومعرّف D1 في `wrangler.toml` ما زال `REPLACE_WITH_YOUR_D1_DATABASE_ID`. لا توجد بيانات محفظة حقيقية أو أسرار دخول ضمن المصدر. اسم حزمة تسليم هذه النسخة `mahfazati-v2.0-react.zip`.

ابدأ بـ[سجل الانتقال إلى React](CHANGELOG_REACT.md). ملفات `تحليل_المشروع.md` و`مراجعة_المتطلبات.md` و`تقرير_المراجعة.html` و`تقرير_التطوير_1.3.html`، وصور المعاينة ذات `v13` أو داخل `preview/legacy`، **وثائق تاريخية للإصدارات السابقة**؛ لا تصف الواجهة أو خطوات التشغيل الحالية.

## تركيب المشروع

- `frontend/`: مكونات React والصفحات والنماذج والأنماط؛ نقطة الدخول `main.jsx`.
- `src/`: خادم Worker والمصادقة ومحرك الحساب والتحقق من اتساق البيانات.
- `public/`: وحدات مشتركة تستخدمها النماذج والخادم والاختبارات؛ لا يُنسخ هذا المجلد إلى النشر. مصدر الواجهة الحالية كله في `frontend`.
- `migrations/`: ترحيلات D1 من `0001` إلى `0004`.
- `tests/`: اختبارات Node وReact؛ اختبارات الواجهة السابقة محفوظة في تاريخ Git والنسخة الأصلية 1.3.
- `dist/`: مخرجات بناء الإنتاج؛ يولّدها Vite ويستبعدها Git.
- `preview/` و`preview-dist/` و`معاينة_تفاعلية.html`: بيانات وأصول المعاينة فقط.

يستخدم التطبيق خط IBM Plex Sans Arabic مستضافًا ضمن أصوله، وأيقونات Lucide. لا يحتاج الخط إلى خدمة خارجية أثناء الاستخدام.

## المعاينة دون تثبيت

افتح `معاينة_تفاعلية.html` مباشرة في المتصفح، ثم اختر المدير أو المساعد من الشريط العلوي. تعرض المعاينة بيانات توضيحية وتدعم التنقل ومراجعة الأشهر والنماذج؛ **لا تحفظ الإضافات والتعديلات**.

لإعادة توليدها من المصدر:

```bash
npm ci
npm run preview:build
```

الأمر يولد ملف HTML مستقلًا بخطه وأصوله المدمجة، ومجلد `preview-dist` كبديل للمعاينة عبر خادم ملفات. يبني Vite المعاينة باستخدام `__PREVIEW__`؛ يستبعد بناء الإنتاج البيانات التجريبية ومسارات تبديل الأدوار. ملف المعاينة ومجلد `preview` والمشغّل المحلي **لا تُنشر** ضمن أصول التطبيق. `wrangler.toml` ينشر `dist` فقط، ويستخدم `src/worker.mjs` كنقطة الدخول مع `run_worker_first = true`.

## تجربة الحفظ محليًا

يتطلب التشغيل **Node.js 24 أو أحدث**. من داخل مجلد المشروع، ثبّت الإصدارات المحددة في ملف القفل ثم شغّل المعاينة:

```bash
npm ci
npm run dev:local
```

يبني الأمر الواجهة إلى `dist` ثم يشغّل الخادم. افتح [http://127.0.0.1:43128](http://127.0.0.1:43128). يظهر شريط بيئة الاختبار وروابط تبديل المدير والمساعد؛ الدور الأول هو المدير. شغّل دور المساعد لتجربة الإضافة والتحصيل والتصحيح. بعد تعديل المصدر، أعد تشغيل الأمر لتحديث البناء؛ هذا المسار لا يعتمد التحديث الفوري لـVite.

يعمل الخادم على `127.0.0.1` فقط ويستخدم SQLite في الذاكرة. ينشئ مفاتيح دخول مؤقتة داخل العملية ويُمرّر الطلبات إلى خادم التطبيق الحقيقي، مع بقاء فحوص الصلاحيات ونسخ السجلات ومصدر الطلب فعالة. طلبات المفاتيح المحلية تُجاب داخل العملية، ولا يوجد اتصال بخدمة خارجية.

البيانات الاصطناعية: عقار ووحدتان وسيارة وعامل، إيجار الشهر الحالي بقيمة 3,000 ريال وتحصيل جزئي 1,200 ريال، أقساط سيارة، التزام هاتف، مصروف 240 ريال، ومهمة. أسماء الحسابات محلية تحت `example.test`.

**تُحذف بيانات التجربة عند إيقاف الخادم** بـ`Ctrl+C`، وتبدأ تجربة جديدة عند تشغيله مرة أخرى. لا تستخدم هذا المسار لحفظ بياناتك الفعلية. لتجربة بداية فارغة:

```bash
npm run dev:local:empty
```

المنفذ الافتراضي `43128`. لتشغيله على `43130`، وهو منفذ معاينة React في جلسة التطوير، استخدم PowerShell:

```powershell
$env:PORT = '43130'
npm run dev:local
```

ثم افتح [http://127.0.0.1:43130](http://127.0.0.1:43130). المتغير `PORT` يسري على جلسة الطرفية الحالية. هذا المشغّل للتطوير فقط، و`npm run dev` اسم آخر للمسار نفسه. عنوان `127.0.0.1` لا يفتح من جهاز آخر أو من الجوال.

## ما أُضيف وأُصلح

- إعادة بناء الواجهة بمكونات React وصفحات ونماذج مستقلة، مع إبقاء خادم التطبيق وقواعد الحساب والصلاحيات.
- اعتماد «إيقاع واضح»: شريط جانبي للكمبيوتر، وتنقل سفلي للجوال، وبطاقات ملخص بقيم ونصوص مركزية.
- خط عربي محلي وأيقونات موحدة، وحالات تحميل وخطأ ونتائج بحث فارغة، وتنقل بلوحة المفاتيح وإدارة تركيز النوافذ.
- فصل بناء الإنتاج عن المعاينة، وإضافة اختبارات سلوك React بـVitest وTesting Library وفحص تضمين الأصول.

وتحافظ النسخة على وظائف وإصلاحات 1.3:

- حفظ حقول الدفعة الأصلية عند إلغائها، حتى إن احتوى طلب الإلغاء على حقول تعديل إضافية.
- فحص أول وآخر استحقاق الإيجار ضمن مدة العقد في النسخ الاحتياطية، ورفض المبالغ المفقودة أو غير الصحيحة بدل تحويلها ضمنيًا.
- إغلاق الاتفاق المسدد وإعادة فتحه بشروط واضحة، مع بقاء الحركات النقدية والتدقيق محفوظين.
- تبويب للاتفاقات المغلقة، مع الاحتفاظ بأسماء الأصول المؤرشفة في التفاصيل والكشوف المرتبطة بها.
- بحث عربي موحد في البطاقات والجداول يشمل أسماء الأصول والمعرّفات وبيانات العقود، مع التعامل مع التشكيل والأرقام العربية.
- عرض الحركات السارية للاتفاق عبر جميع الأشهر داخل تفاصيله، وروابط من التنبيهات إلى السجل أو العقد المرتبط.
- كشف شهري للطباعة وتصدير الحركات إلى CSV، مع فصل الاستحقاقات عن التنفيذ النقدي.
- مقارنة المبالغ في الواجهة بالهللات الصحيحة، وتحسين ترتيب المعلومات وعرض الجوال وحالات الاتصال.
- عرض عربي من اليمين إلى اليسار، وفصل واضح بين أرقام المراجعة وإجراءات الإدخال.

استمرت حمايات 1.2: منع تكرار الكتابة، ورفض التعديلات المبنية على إصدار قديم، ومنع تداخل الإيجار والتنافس على الرصيد، والتوزيع المقيد للدفعة الزائدة، وحماية سجل التدقيق.

## إغلاق الاتفاق وإعادة فتحه والأرشفة

من «تفاصيل الاتفاق»، يستطيع المساعد إغلاقه إذا أصبح المتبقي صفرًا. عقد الإيجار يتطلب كذلك انتهاء مدته؛ يصبح الإغلاق متاحًا بدءًا من اليوم التالي لتاريخ النهاية بتوقيت الرياض. الإغلاق يدوي ولا يحدث تلقائيًا بمجرد السداد.

يبقى تاريخ التحصيل والسداد ظاهرًا في أشهر التنفيذ بعد الإغلاق. يمنع الاتفاق المغلق إدخال دفعة أو تعديل بياناته وحركاته حتى إعادة فتحه. إعادة الفتح تتطلب أصلًا غير مؤرشف، وللإيجار تتطلب عدم تداخل الفترة مع عقد مفتوح آخر.

بعد إغلاق الاتفاق، يمكن أرشفة أصله إذا لم تبقَ اتفاقات مفتوحة أو وحدات غير مؤرشفة مرتبطة به. الأرشفة تُخفي الأصل وتحفظ تاريخه. لا يوجد مسار لإلغاء الأرشفة في هذه النسخة؛ إذا احتجت تصحيح حركة، أعد فتح الاتفاق قبل أرشفة أصله.

إلغاء جدول بلا دفعات نشطة يظل عملية منفصلة عن إغلاق اتفاق مسدد. بعد وجود دفعات، تُحمى القيمة والجدولة الأصلية، ويبقى التصحيح من خلال الحركات. إذا تعارض تصحيح حركة قديمة مع حركات لاحقة، يُرفض الطلب كاملًا وتظهر إرشادات مراجعتها من الأحدث إلى الأقدم.

## الكشف الشهري والتصدير

اختر الشهر من الرئيسية للمدير أو من التحصيل والسداد، ثم اضغط «كشف الشهر». يحتوي الكشف على استحقاقات الشهر، والمنفذ منها، والمتبقي، والحركات النقدية بتاريخ تنفيذها. «طباعة الكشف» يستخدم طباعة المتصفح؛ ويمكن اختيار الحفظ بصيغة PDF إذا وفره المتصفح.

«تصدير الحركات CSV» يصدّر الحركات السارية المنفذة خلال الشهر المختار، بما فيها الحركات التابعة لاتفاق مغلق. الملف يدعم النص العربي ويعالج النصوص التي قد تُفسّر كصيغ في برامج الجداول. لا يتضمن CSV كامل النسخة الاحتياطية أو جميع الاستحقاقات.

الكشف يعكس آخر بيانات محملة، وليس لقطة تاريخية ثابتة قبل التصحيحات. القيم المدفوعة قبل تأسيس المحفظة لا تدخل في النقد الشهري. صافي التدفق هو الداخل ناقص الخارج خلال الشهر، ولا يمثل رصيد حساب بنكي.

## الاختبارات المحلية

بعد `npm ci`، شغّل من مجلد المشروع:

```bash
npm test
npm run build
npm run review:probes
npm run preview:build
```

`npm test` يشغّل `test:core` باختبارات Node ثم `test:react` باستخدام Vitest وjsdom وTesting Library. تشمل التغطية الحساب بالهللة والتواريخ والتوزيع وفحص النسخ والترحيلات والصلاحيات والتزامن وإعادة المحاولة والإغلاق وإعادة الفتح والبحث والكشف والتصدير وسلوك النماذج. يعرض خرج الجولة عدد الاختبارات ونتائجها؛ لا تنقل أعداد وتقارير الإصدار القديم لتقييم هذه النسخة. `review:probes` مجموعة قبول للمشكلات التاريخية الثلاث ولا يغني عن المجموعة الكاملة.

استُبدلت الاختبارات القديمة المبنية على دوال `public/app.js` باختبارات مكونات React. حُذفت ملفات الواجهة القديمة `public/app.js` و`public/index.html` و`public/style.css` من النسخة الحالية؛ تبقى في تاريخ Git والنسخة الأصلية 1.3، مثل اختبارات العميل السابق. يفحص اختبار البناء غياب بيانات المعاينة من الإنتاج وصلاحية معاينة React المدمجة وخطوطها.

تستخدم اختبارات الخادم SQLite وتوقيعات دخول محلية، وتستخدم اختبارات React بيئة DOM محاكاة. الاختبار المحلي لا يثبت سلوك Cloudflare Access أو D1 في البيئة المنشورة أو يغطي جميع المتصفحات والأجهزة. لقطات وتقارير 1.3 توثّق مراجعة الواجهة السابقة فقط.

## ترقية قاعدة بيانات موجودة

الترحيل `migrations/0004_agreement_closure.sql` يضيف `closed_at` و`closed_by` وفهرسًا، ويحدّث حمايات العلاقات والإغلاق والإيجار والدفعات. الاتفاقات الموجودة تبقى مفتوحة، ولا يُعاد إنشاء قاعدة البيانات أو حذف حركاتها. لا تعِد تنفيذ ملفات التأسيس يدويًا على قاعدة قائمة.

1. صدّر نسخة مستقلة من البيانات القائمة واحتفظ بها خارج مجلد التجربة.
2. افحص ملف JSON بأمر القراءة فقط:

```bash
node scripts/check-backup.mjs /path/to/mahfazati-backup.json
```

3. إذا كانت `ok:false`، راجع السجلات المذكورة قبل الترقية. يُقبل غياب أعمدة الإغلاق وإيصالات الطلبات في صيغ التصدير القديمة؛ لا يقوم الفحص بإصلاح البيانات أو استعادتها.
4. راجع جداول النسخ القديمة التي استُخدم فيها توزيع الزيادة `spread`، ثم جرّب الترحيلات على نسخة مستقلة من البيانات.
5. أوقف الإدخال خلال الانتقال، وطبّق الترحيلات غير المنفذة بالترتيب، ثم ابنِ الواجهة وحدّث الخادم و`dist` معًا وأعد تحميل الصفحات المفتوحة. الانتقال إلى React لا يضيف ترحيل قاعدة بيانات بعد `0004`.

التصدير الجديد يحمل `format_version:2` و`schema_version:4`. فحص النسخة يغطي قواعد اتساق محددة؛ لا يثبت صحة كل معلومة أو نجاح الاستعادة.

## إعداد النشر والفحوص المتبقية

يتطلب النشر حساب Cloudflare وقاعدة D1 وتطبيق Cloudflare Access على النطاق المقصود. يجب ضبط سياسة Access للحسابين الحقيقيين، وإبقاء `run_worker_first = true` لحماية الملفات وواجهة API. يحتوي `wrangler.toml` على خانة صريحة لمعرف قاعدة البيانات، ولا يحتوي أسرارًا أو حسابات إنتاج جاهزة.

الأوامر التالية للإعداد اللاحق، ولم تُنفّذ على حسابك:

```bash
npm ci
npx wrangler login
npx wrangler d1 create mahfazati-db
```

استخدم معرف قاعدة موجودة عند ترقية محفظة قائمة؛ أمر الإنشاء لقاعدة جديدة. ضع المعرف الصحيح في `database_id` واضبط إعدادات الدخول:

```bash
npx wrangler secret put ACCESS_TEAM_DOMAIN
npx wrangler secret put ACCESS_AUD
npx wrangler secret put MANAGER_EMAIL
npx wrangler secret put ASSISTANT_EMAIL
```

بعد النسخ والفحص وتجربة الترحيل في بيئة مستقلة:

```bash
npx wrangler d1 migrations apply mahfazati-db --remote
npm run deploy
```

`npm run deploy` ينفذ `npm run build` ثم `wrangler deploy`. يمكن تنفيذ `npm run build` وحده لمراجعة مخرجات الإنتاج دون نشر. احتفظ بـ`package-lock.json` في GitHub، ولا ترفع `node_modules` أو `dist` أو `preview-dist` أو `.wrangler` أو ملفات الأسرار؛ يتولى `.gitignore` استبعادها عند استخدام Git. رفع الملفات يدويًا عبر موقع GitHub لا يطبق قواعد الاستبعاد تلقائيًا.

قبل الاعتماد الفعلي، يلزم اختبار دخول الحسابين ورفض حساب ثالث، وتطبيق ترحيلات D1، والحفظ من جلستين، والتصدير ومطابقة الإجماليات، والاستعادة في بيئة منفصلة. لم يُجرَ نشر إنتاجي أو هذا التحقق على Cloudflare حقيقي ضمن التسليم. لا تستخدم `preview-dist` أو مشغّل الاختبار المحلي كاستضافة للتطبيق الحقيقي.

## إعادة المحاولة والنسخ والحدود الحالية

إذا لم يصل تأكيد الحفظ، أعد إرسال البيانات نفسها. تحتفظ جلسة التبويب ببصمة الطلب ومعرفه وإصداره فقط، دون محتوى الحقول. عند تعذر التخزين، تكون الحماية في ذاكرة الصفحة؛ إغلاق الجلسة أو تبديل الجهاز لا يستعيد نية الإرسال، لذا راجع السجل قبل إدخال العملية من جديد.

نسخة المدير JSON غير مشفرة وتشمل المؤرشف والملغى والتدقيق وإيصالات الطلبات وبيانات الإغلاق. لا يوجد زر استعادة من JSON أو نسخ خارجي مشفر مجدول. يلزم ترتيب حفظ النسخ واستعادتها قبل الاستخدام الحقيقي.

التطبيق لمحفظة صغيرة، ولا يدعم تعدد العملاء أو العمل دون اتصال. باستثناء سجل العمليات، تُحمّل بيانات المحفظة مجتمعة؛ يلزم قياس الأداء على حجم البيانات الفعلي. التنبيهات داخل التطبيق فقط، ولا توجد رسائل هاتف أو إشعارات خارجية.
