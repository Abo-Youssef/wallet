تحليل محفظتي — مراجعة 1.2 بتاريخ 15 أكتوبر 2026

تمت مراجعة ملفات المصدر والإعدادات والترحيلات والاختبارات والمعاينة والتوثيق، وتنفيذ إصلاحات مثبتة، مع الحفاظ على هوية محفظتي والأدوار المالية الحالية. لم يحدث نشر أو ربط باستضافة أو تعديل لبيانات حقيقية. البيانات الفعلية مؤجلة حتى توفر الجهاز الآخر.

لا يمكن إثبات انعدام جميع الثغرات من مراجعة محلية. النتيجة هنا إصلاحات قابلة للفحص واختبارات محددة، مع بيان ما لم يُختبر بدل وصف الحزمة بأنها إطلاق نهائي.

منهج التفكير العكسي

بدأت المراجعة من النتائج الخاطئة التي قد تبدو صحيحة على الشاشة: مصروف واحد يُسجّل مرتين، عقدان يستأثران بالوحدة نفسها، طلب قديم يمحو تعديلًا حديثًا، تحصيل يزيد قسطًا آخر، أو رسالة نجاح لا تطابق نتيجة الحفظ. ثم تتبعت كل نتيجة عبر النموذج وواجهة API ومحرك الحساب ومعاملة قاعدة البيانات وسجل التدقيق.

سجل العمليات والفترات

الفترات تشمل الكل واليوم وآخر 7 أيام والشهر حتى اليوم والعام حتى اليوم وفترة من/إلى، مع إمكان استخدام حد واحد. اليوم محسوب بتوقيت الرياض، والفرز تصاعدي أو تنازلي. يُطبق الشرط داخل قاعدة البيانات قبل تحميل 50 سجلًا، ثم يمكن تحميل المزيد؛ لا يوجد سقف 300 سجل.

الفترة تتعلق بوقت تسجيل الإضافة أو التعديل أو الإلغاء، لا بتاريخ التحصيل الفعلي. يظل السجل الأصلي محفوظًا عند الإخفاء بواسطة المدير. أضيفت مقارنة القيم السابقة والجديدة، ومنع تسجيل إخفاء أو إتمام تنبيه مكرر كحدث جديد، والتحقق من أن مفتاح التنبيه حقيقي.

الواجهة والهوية وتجربة الاستخدام

  • احتُفظ باسم محفظتي واللون الكحلي والخلفية الهادئة، مع أيقونات متجانسة في الشريط العلوي والتبويبات أسفله.
  • وُسطت العناوين والتسميات والحقول والأرقام وخلايا الجداول وأزرار النماذج. بقي اتجاه الصفحة عربيًا، والتواريخ والأرقام في اتجاه مناسب للقراءة.
  • أصبحت مساحة اللمس الأساسية 44 بكسل أو أكثر، وتلتف الأزرار بدل خروجها من البطاقة، وتتحول النماذج إلى عمود على الشاشات الضيقة. تمرير الجدول داخل منطقته.
  • النوافذ تعزل الخلفية، وتدير الانتقال بلوحة المفاتيح، وتعيد التركيز عند الإغلاق، وتمنع الإغلاق أثناء الحفظ وتسأل عند ترك تغييرات غير محفوظة.
  • رسائل أخطاء النموذج داخل النافذة؛ وتعارض النسخة يتيح تحديث البيانات. حقول المبالغ تستخدم منزلتين، وعدد الأقساط عدد صحيح بين 1 و600.
  • الحركات المنفذة والمصروفات تتبع الشهر المختار. الاستحقاقات لها نطاق واضح: الشهر أو جميع الفترات. أزيل الإخفاء الصامت لما بعد 40 حركة، وأضيف «عرض المزيد» لجدول أعمال المساعد.
  • يستطيع المدير فتح تفاصيل الأصل والاتفاق. أضيف إلغاء الاتفاق الذي لا يحتوي دفعات نشطة من شاشة تفاصيله.
  • العرض يحمي نفسه من استجابة قديمة تصل بعد تغيير الشهر أو فترة السجل، ويحتفظ بالبيانات السابقة مع رسالة تحديث عند فشل الاتصال.
  • البيانات التوضيحية منفصلة في المعاينة؛ التطبيق الحقيقي يعتمد API فقط ولا يبدل البيانات الحقيقية بأرقام افتراضية عند الخطأ.

لم يتوفر متصفح محلي صالح للفحص البصري أو لمسارات التفاعل الفعلية. لذلك هذه تعديلات في الواجهة والمنطق مع تحقق آلي محدود، وليست شهادة بأن المحاذاة اجتازت مراجعة بصرية على كل جهاز. افتح المعاينة الحالية للمراجعة؛ صور preview/legacy/ من التصميم السابق.

التحقق والحدود العملية

نجح 55 اختبارًا محليًا على Node.js 24.19.0. تستخدم اختبارات API قاعدة SQLite مؤقتة وتوقيعات RSA محلية؛ وتُجبر اختبارات التزامن الطلبين على إنهاء القراءة قبل السماح بالكتابة، بدل الاكتفاء بإرسال متتابع. تتحقق الاختبارات من الرصيد وعدد السجلات والتدقيق، لا من حالة HTTP وحدها.

هناك حدود باقية محددة:

  1. لا توجد بيانات المستخدم الحالية في هذه البيئة. عند توفرها، افحص نسخة التصدير قبل الترقية، خصوصًا اتفاقات spread القديمة؛ قد يتغير توزيع المتبقي أو تتعارض معه دفعة لاحقة. لا يجوز حذف الحركات أو تعديلها تلقائيًا لمجرد اجتياز الفحص.
  2. لم تُختبر Cloudflare Access أو D1 الفعلية أو النطاق والأسرار والاستعادة. اختبارات SQLite لا تستبدل قبول البيئة المنشورة.
  3. لم يُجر اختبار بصري أو متصفح فعلي. يلزم تجربة الجوال والكمبيوتر ولوحة المفاتيح عمليًا.
  4. لا توجد استعادة JSON داخل الواجهة، أو خدمة نسخ مشفرة مجدولة، أو إشعارات هاتف خارج التطبيق.
  5. أصل مرتبط باتفاق نشط لا يُؤرشف حتى مع اكتمال السداد. لا يوجد سير عمل لإغلاق اتفاق مدفوع وإعادة فتحه؛ الإلغاء المتاح يخص الاتفاقات بلا دفعات نشطة.
  6. أي تصحيح قديم يُفسد تسلسل حركات لاحقة يُرفض كاملًا؛ لا توجد تسوية محاسبية متعددة الخطوات داخل نافذة واحدة.
  7. الحماية من إعادة الإرسال تتبع معرّف الطلب. بعد إغلاق جلسة التبويب أو استخدام جهاز آخر، يجب مراجعة السجل قبل إنشاء طلب جديد مستقل.
  8. التطبيق لمحفظة واحدة مشتركة بين حسابين، وليس منتجًا متعدد المحافظ المعزولة. ما عدا سجل العمليات، تُحمّل البيانات مجتمعة؛ قياس الأداء ينتظر حجمًا واقعيًا.
  9. لم يُجر تدقيق مستقل لكود أداة النشر Wrangler أو فحص اختراق خارجي. إعداد الأداة واعتماد نسخة تثبيت محددة يُراجعان عند إعداد الاستضافة.

مراجع القرار التقني

  • توثيق Cloudflare D1: المعاملات المجمعة — يوضح أن فشل عبارة داخل الدفعة يعيد المعاملة كاملة؛ عليه بُني حفظ التغيير والإيصال والتدقيق معًا.
  • توثيق Cloudflare Access: التحقق من JWT — مرجع جهة الإصدار وجمهور التطبيق ومفاتيح التوقيع.
